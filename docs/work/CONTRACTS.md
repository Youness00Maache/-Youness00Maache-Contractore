# ContractorDocs: rebuild contracts (read this before you change anything)

Several engineers (agents) work **in the same working tree at the same time**, each owning a set of files.
This file is the shared contract. If you need to change a contract, add a dated note under "Change log" at the
bottom (append only; never rewrite another agent's lines).

## 0. Ground rules
- **Only edit files you own** (see §1). Other files are read-only for you. If you need a change in a file you don't own,
  append a request to `docs/work/HANDOFFS.md` (who → whom, file, exact change, why) and code against the intended result.
- **Re-read a file right before editing it.** Others are editing nearby files; never write from a stale copy.
- **Never run** `git commit`, `git push`, `git reset`, `git checkout -- .`, `git stash` or any destructive git command. Never delete files you don't own.
- **Never** stop or remove the Docker containers whose names end in `_dd` (another project of the owner).
- Do not start the Vite dev server or browser tests: final end-to-end browser testing is done centrally. Verify with:
  - `npx tsc --noEmit -p .` (slow: run it once or twice, then filter the output to YOUR files), and
  - small `npx tsx <script>` checks for pure logic, and
  - `npx vite build` once at the end (only if no other agent is clearly mid-way through breaking changes; a build error in someone else's file is not yours to fix: note it in your report).
- The audit is the spec: `PROJECT_AUDIT/00_README.md` + the area report(s) named in your brief. Fix every issue in your area
  (Critical → Low) unless it's clearly obsolete; list anything you deliberately skip in your final report with the reason.
- Product goal: a polished, consistent, trustworthy SaaS that contractors would pay for. No dead buttons, no "coming soon"
  placeholders in shipped UI (either implement it or remove the control), no `alert()` for normal UX (use the toast or inline
  messages that already exist in the code; if none, inline error text), no console noise (`console.log` debugging).

## 2. Platform facts
- React 18 + Vite 5 + TypeScript. Tailwind is now **build-time** (tailwind.config.js + index.css). No CDN scripts at all.
- Supabase client: `import { supabase, invokeFunction } from '<rel>/lib/supabase.ts'`. Do NOT create other clients and do not use `window.supabase`.
  Components may still receive `supabase` as a prop (legacy). It's the same instance.
- PDF libs come from npm (`jspdf`, `jspdf-autotable`, `html2canvas`), already wired in `services/pdfGenerator.ts`.
- Local dev backend: Supabase CLI stack on **API http://127.0.0.1:56321**, DB port 56322, Studio 56323, Mailpit (emails) 56324.
  `.env.local` holds `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` for it. Production values are set in Vercel later.
- Edge functions are Deno. Secrets they may read: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
  `GEMINI_API_KEY`, `GEMINI_MODEL` (default `gemini-flash-latest`), `KELVIQ_SERVER_API_KEY`, `KELVIQ_WEBHOOK_SECRET`,
  `KELVIQ_ENV` (`live`|`sandbox`), `KELVIQ_PRODUCT_ID`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SITE_URL`, `TOKEN_ENCRYPTION_KEY`.
  Every user-facing function must verify the caller's JWT (`supabase.auth.getUser(token)`) and scope all reads/writes to that user.
  Webhooks verify signatures. CORS: allow `SITE_URL`, `http://localhost:3010`, `http://127.0.0.1:3010` (reflect if in allow-list).

## 3. Money, escaping, plans (use these, don't re-implement)
- `utils/money.ts`: `computeDocumentTotals(data)` → `{subtotal, discount, taxableAmount, taxRate, tax, shipping, total, amountPaid, balanceDue}`,
  `lineItemAmount(item, isProgress)`, `toNumber()`, `roundMoney()`, `formatMoney(value, currency)`. Discount and shipping are flat amounts, tax is a % applied after discount, shipping is not taxed.
  Progress billing line amount = max(0, qty×rate×pct/100 − previouslyBilled).
- `utils/escapeHtml.ts`: `esc()`, `escMultiline()`, `safeUrl()`, `sanitizeRichText()`. Every user/AI value placed in an HTML string must be escaped/sanitized. No raw `dangerouslySetInnerHTML` with unsanitized data.
- `lib/plans.ts`: tiers `free | premium | ai`, `FREE_LIMITS`, `PLANS`, `isPaidTier()`, `normalizeTier()`. Prices: Premium $5/mo or $50/yr; Premium + AI $10/mo or $100/yr.
- `lib/billing.ts`: `startCheckout(tier, period, userId)` → `{url}` (then `window.location.assign(url)`), `getBillingPortalUrl()`. PayPal is removed completely.

## 4. Database contract (BACKEND writes `supabase/migrations/*.sql`; everyone else codes to it)
- Column names are **snake_case** in the DB. The app maps to camelCase in code. Existing column names used by the current code are canonical unless BACKEND records a change in the change log below.
- Tables in use: `profiles`, `jobs`, `clients`, `documents`, `saved_items` (price book), `inventory`, `inventory_history`, `forum_posts`, `forum_comments`, `forum_votes`, `forum_comment_votes`, `notifications`, `ai_chat_history`, `user_gmail_accounts`, plus new `billing_events`, `usage_events`.
- `profiles` billing fields (written ONLY by service role / webhook, never by the browser): `subscription_tier` (`free|premium|ai`), `subscription_status` (`active|past_due|cancelled|paused|none`), `subscription_period_end`, `kelviq_customer_id`, `kelviq_subscription_id`, `ai_credits_used`, `ai_credits_period_start`.
- `documents.data` is JSONB holding the camelCase form data object; `documents.type` is the FormType string.
- RPCs (names/args kept compatible with the current frontend; BACKEND makes them safe):
  - `get_portal_data(p_key text)` → `{ client, contractor, documents[] }` with only whitelisted, client-safe fields.
  - `sign_document_via_portal(...)` (keep current args) → only for documents that belong to the portal's client; stores the client signature separately (`data.clientSignatureUrl`, `data.clientSignedAt`, `data.clientSignerName`), never overwrites the contractor's signature.
  - `get_document_by_token(doc_token text)`, `approve_document_by_token(...)` (keep current args).
  - NEW `mark_documents_viewed(p_document_ids uuid[])`: sets `data.viewedByProvider = true` server-side (jsonb_set), owner only. Replaces the client-side full-document overwrite.
  - NEW `get_my_usage()` → `{ tier, status, jobs_this_month, clients_total, emails_this_month, ai_this_month, limits }`.
  - NEW `record_usage(p_kind text)` for `email` / `ai` counters (or the edge functions record usage themselves).
  - Free-plan limits are enforced in the DB too (insert triggers on `jobs`, `clients`, `documents`) and raise an error whose message starts with `PLAN_LIMIT:` so the UI can show the upgrade modal.
- Inventory stock changes happen **only** in the database (triggers / RPC), idempotently. The frontend must never do read-modify-write of `inventory.quantity`.
